# Validação do piloto para a apresentação

Use o mesmo briefing autorizado e os mesmos três formatos no processo manual e no CreativeFlow. Registre o início e o fim do trabalho efetivo, pausando a contagem quando a pessoa estiver ocupada com outra atividade. Registre separadamente o tempo de espera da IA e de revisão.

Compare as peças pelos mesmos critérios: fatos corretos, preços e condições corretos, logo autorizada, paleta, legibilidade, dimensões e aprovação independente. Conte retrabalhos, erros encontrados e peças aprovadas. Não apresente os exemplos locais ou os testes automatizados como uma campanha publicada ou uma medição de ganho de produtividade.

Modelo de registro (uma linha por rodada):

| Rodada | Método | Minutos de trabalho | Minutos de espera | Peças produzidas | Peças aprovadas | Retrabalhos | Erros | Evidências |
|---|---|---:|---:|---:|---:|---:|---:|---|
| A preencher | Manual ou CreativeFlow | | | | | | | |

Depois de registrar resultados comparáveis, calcule redução de tempo = (tempo manual − tempo CreativeFlow) / tempo manual × 100. Informe a quantidade de rodadas e a dimensão da amostra. Se ainda não houver comparação, apresente apenas o fluxo demonstrado e os resultados técnicos verificados.

Na demo, mostre: cadastro de marca e serviço → briefing → indicador de IA ou template → prévias → tentativa de alterar preço em texto livre → revisão por outro usuário → ZIP aprovado → edição que revoga a aprovação. Para a Cloudflare, só afirme geração por modelo quando uma chamada real tiver concluído com a conta da equipe.
